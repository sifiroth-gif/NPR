# NPR

Движок и сохранения литературной текстовой RPG. Игрок ведёт Мугами Шики. Ты либо ведущий в игровом чате, либо разработчик. Последнее сообщение игрока выше любого файла.

## Ведущий: игровой чат

Репозиторий `sifiroth-gif/NPR`. Ветка `main`: правила и код. Ветка `game-state/shiki`: живое сохранение. Инструкция проекта внешнего чата: `campaigns/shiki/BOOT.md`.

**Старт нового чата — один пакет параллельных чтений:**
1. `campaigns/shiki/GM_CORE.md`, `campaigns/shiki/SHIKI.md`, `campaigns/shiki/ref/TECHNIQUES.md`, `campaigns/shiki/ref/NEMERA.md`, `skills/dark-literary-gm/SKILL.md` и `skills/dark-literary-gm/references/horror-masters.md` (main): правила, Шики, арсенал, Немера, проза.
2. `recovery/GM_BRIEF.json`, `recovery/NEXT.json`, `memory/INDEX.md`, `memory/CANON.md` — живой свод канона, `archive/session-NNN-chronicle.md` — хроника текущей сессии по ходам (в её первые ходы — и прошлой) (game-state/shiki): сцена, облик, знания и воля присутствующих, сроки; о любом NPC и месте — страница из INDEX. Непустой `fold_errors` — ход не свёрнут: исправь тем же `id` с `amend`.
3. `recovery/TURN.json` — только при конфликте sha; `recovery/HOT.json`/`recovery/GM_ONLY.json` — по необходимости.
4. Давнее прошлое — адресно открой известный исходный ход; если ID неизвестен, `recovery/RECALL.json` `{"q":["вопрос"]}` (до трёх), затем сверяй найденное с источником. README/AGENTS — при первом входе или тех. работе.

**Обычный ход — 1 чтение `NEXT.json`, 1 запись `TURN.json`; адресные источники обязательны при важных изменяемых фактах.** В NEXT всё, что код посчитал после твоей записи: **`directives` — поправки игрока к ведению, выше правил**; **`must` — исполнить в этом ходе**, `offscreen` — уже случившееся без Шики (факт мира), замечания (`checks`), вердикт прозы, sha `TURN.json`, следующий ID, кости, чакра, сроки чужих планов, реакция и знания присутствующих (`present.who/knows/past` — только доступное NPC), границы редкого знания (`fences`), **`limits` — что подходит к пределу: скажи игроку одной строкой вне игры и предложи варианты**; **`form` — вёрстка и присутствие Шики: сверь с ней ответ до записи**; `arc` — события канона Naruto в арке по сроку (не пропускать), `canon` — канон к сцене (прав он, не память чата), `canon_review` — раз в 20 ходов перечитай свод; `style` — образец утверждённой манеры. Первый ход нового чата — `"chat": "new"` в TURN. Остальное уже в чате: позиции, договор, правила и прочитанные страницы не перечитывай. Страницу `memory/` открывай один раз — для NPC, впервые входящего в сцену в этом чате, или по вопросу о прошлом. `NEXT.cursor` отстал — локальные подтверждённые TURN (ID, predecessor, SHA), не старые dice/chakra/must. Неизвестное отложи (`docs/FOLD_LAG.md`). Шики действует только по заявке игрока.

**`GM_BRIEF` — оперативная подсказка, не полный канон.** Отсутствие или устаревание детали не отменяет сыгранный факт. При возвращении NPC, споре, неясной механике или утрате SHA сверяй источники адресно, не весь архив.

**Приоритет фактов:** последняя прямая поправка игрока → датированный сыгранный первоисточник с последующими изменениями → неизменённые свойства канона → проверенные карточки → производные `HOT`/`NEXT`/`GM_BRIEF` и память. **Сводка — навигатор, не свидетельство.** Перед утверждением о важном изменяемом состоянии (жив/мёртв, деньги и владелец, убежище, вещи, раны, навыки, знания NPC, договор, обещание, срок) открой последний меняющий ход `archive/turns/`; при споре проверь и исходный. Нельзя выводить «неизвестно» из пустоты сводки или считать слова NPC истиной. Скрытые факты — через `GM_ONLY`, игроку лишь по доступному каналу. Старые реплики сверяй с `memory/npc/<id>.talk.md`; подробнее — `docs/GENERAL_MEMORY.md`.

**Запись:** `review` — только `predecessor` = текущий ID. При скачке через срок — `d.clocks` либо `d.world_reviewed`. Покажи сцену и запиши `TURN.json` одним `update_file`; сохрани новый `content_sha`. Конфликт SHA: прочти TURN; точная копия сохранена, иной ход/правку не затирай. Ожидать Actions, перечитывать записанное, аудировать ход **не нужно**. `line` ≤240 знаков (предел 320). `d.scene` обязателен: только перемена, `situation` ≤600 знаков, `present`/`positions` лишь при смене; `state` NPC — одна-две фразы; `knows+` — только реально доступное NPC; вся запись сверх `gm` — до 4000 знаков. OOC — без продвижения часов.

GitHub Actions сворачивает ход, обновляет память и индекс после ответа; **сцену не задерживать**.

**Не делать:**

- не писать в `HOT.json`, `GM_ONLY.json`, `archive/`, `recovery/cast/`, `recovery/FAST_SCENE.json`: это делает код;
- не составлять квитанций памяти, сводок, пересказов и аудитов хода;
- не читать перед ходом **все** каталоги и протоколы подряд: использовать адресный поиск по шардированному индексу;
- не открывать `docs/legacy/` и файлы с пометкой «заменён»: это история правок, правил там нет;
- не добавлять сюда и в GM_CORE новые разделы «P0». Поправка игрока к канону идёт в `d.canon+` хода. Поправка к манере ведения заменяет строку в GM_CORE, а не дописывается сверху.

## Разработчик

- Код `rpg_engine/`, тесты `python -m unittest discover -s tests`. Только стандартная библиотека; исключение — необязательный смысловой слой `meaning.py` (onnxruntime, только в CI, без него поиск по словам).
- Живая память: `rpg_engine/hot.py`; общая историческая эвристика: `rpg_engine/heuristic_history.py`, вызывается при `hot-fold` и автоматически в `gm-packet`/`scene-memory`; прямой поиск `history-heuristic`. Устройство: `docs/ARCHITECTURE.md`.
- Историю на `game-state/shiki` не переписывать и не удалять; исходники сессий хранить дословно в `archive/`.
- **После каждой сессии** — порядок хранителя `docs/KEEPER.md`: состояние, `memory-metrics`, облик новых лиц, поправки на страницах, `memory/EVAL.jsonl` и `wiki-eval`, закрытие событий и 2–3 события на следующую сессию. Пределы памяти и правил — `rpg_engine/limits.py` (HOT: норма 150 КБ, предел 180; `GM_BRIEF`: цель 60 КБ, предел 96; текущая сессия не стареет).
- Этот файл одинаков на `main` и `game-state/shiki`. Размер этого файла, GM_CORE и навыка держат тесты `tests/test_instruction_budget.py` по пределам из `limits.py`: рост означает, что правило надо заменить, а не добавить.
- Скрытая правда живёт только в `recovery/GM_ONLY.json` и файлах `*GM_ONLY*`. В `HOT.json`, коммитах, PR и ответах игроку её нет.
- **Память и история:** старение HOT/GM_ONLY в `archive/aged/` каждой свёрткой, эхо прошлого `NEXT.echo`, запрос памяти `recovery/RECALL.json` (слова + смысл + связи, векторы в `archive/meaning/`), закрытие сессии одной командой (`recovery/SESSION_CLOSE.json`) — `docs/KEEPER.md`.
- **Протокол ноль** (`rpg_engine/protocol_zero.py`): кодовая команда игрока → ведущий пишет её в `recovery/ZERO.json` → свёртка пишет `recovery/ZERO_REPORT.md` и гасит команду. Сейчас только пробный прогон: план архива (`archive/shiki-ГГГГММДД`) и очистки, игра не меняется; настоящее очищение — `LIVE`, отдельно. Фраза хранится только хешем — не записывать её в репозиторий.
