# NPR

Движок и сохранения литературной текстовой RPG. Игрок ведёт Мугами Шики. Ты либо ведущий в игровом чате, либо разработчик. Последнее сообщение игрока выше любого файла.

## Ведущий: игровой чат

Репозиторий `sifiroth-gif/NPR`. Ветка `main`: правила и код. Ветка `game-state/shiki`: живое сохранение. Инструкция проекта внешнего чата: `campaigns/shiki/BOOT.md`.

**Старт нового чата — один пакет параллельных чтений:**
1. `campaigns/shiki/GM_CORE.md`, `campaigns/shiki/SHIKI.md` и `skills/dark-literary-gm/SKILL.md` (main): правила, Шики, проза.
2. `recovery/GM_BRIEF.json`, `recovery/CHECKS.json`, `memory/INDEX.md` (game-state/shiki): сцена, облик и знания присутствующих, кости, сроки, sha `TURN.json` (`turn_file`); о любом NPC и месте — страница из INDEX. Непустой `fold_errors` — ход не свёрнут: исправь тем же `id` с `amend`.
3. `recovery/TURN.json` — только при конфликте sha; `recovery/HOT.json`/`recovery/GM_ONLY.json` — по необходимости; `memory/SCENE.md` — сцена для человека.
4. `archive/heuristic-recall/manifest.json` читать **только при адресном историческом поиске**. README/AGENTS — при первом входе или тех. работе.

**Обычный ход — быстрый путь:** если тот же эпизод и его действующие NPC/часы уже известны из текущего чата, **0 поисков, 0 повторных чтений, 1 запись** `recovery/TURN.json`. Перед новым признанием NPC проверь `scene.npc_disclosures_to_player` в HOT (источниковые подсказки, не факты); при сомнении открой исходный ход. Сохраняй в контексте последний `content_sha` GitHub и следующий ID. Применяй действие игрока, самостоятельный ход NPC и ближайшие часы, пиши сцену. Не перечитывай уже известные позиции, стадию договора и механики; Шики действует только по заявке игрока.

**`GM_BRIEF` — оперативный L0, не полный канон.** Отсутствие детали в нём не отменяет карточку, скрытое состояние или сыгранный факт. Полная память — адресно в L1/L2; источник проверяется перед новым историческим утверждением.

**Когда читать заново:** новая сессия, существенный переход, возвращение NPC, неясная механика, конфликт канона, скрытые часы или утрата SHA. Тогда адресно читай HOT/GM_ONLY/TURN и нужную страницу, не всю историю.

**Исторические ответы NPC — обязательный предсценный контроль:** если игрок спрашивает, что NPC **раньше говорил, скрывал, обещал, предъявлял или знал**, сначала проверь сообщения этого NPC и конкретные первоисточники, даже в **текущей** сессии. `python -m rpg_engine scene-gate --state-dir _state --player-action '...' --actor <id>` выдаёт сыгранные раскрытия, их ID и граф порядка; `--draft` с `--reviewed <turn-id>` не допускает непроверенный черновик. Не выдавай пересказ известного за **новое** откровение. Знания NPC ≠ сказанное игроку ≠ доказанный факт. Без локальной копии читай `archive/session-NNN-turns.jsonl` через GitHub и сверяй точные ходы, не изображай запуск проверки. Для других сессий используй `route-*` → `shard-*` эвристического индекса, затем первичный сыгранный текст и поздний канон. Рутинное действие без исторических утверждений не запускает поиск. Смотри `docs/UNIFIED_RECALL.md`.

**Публикация и запись:** сначала проверь `GM_BRIEF`: раскрытия NPC, сроки и планы NPC (`agendas`). Для каждого игрового TURN добавь `review.predecessor` = текущий ID. Прежние слова NPC — `present_npcs.prior_disclosures` и `npc/<id>.talk`: старое не выдавай за новое. При скачке через срок обработай `d.clocks` либо `d.world_reviewed`. Затем покажи сцену и запиши `TURN.json` одним `update_file`; сохрани новый `content_sha`. Если запись не удалась, сообщи; при конфликте SHA — единственное повторное чтение TURN и повтор того же ID. Ожидать Actions, перечитывать записанное, запускать SQLite, аудировать каждый ход **не нужно**. `line` — цель ≤240 знаков, предел 320. `d.scene` обязателен для игрового хода; записывай изменения, а не пересказ `gm`; `present` и `positions` лишь при смене. `knows+` — только реально доступные NPC знания. OOC фиксируй без продвижения часов.

GitHub Actions сворачивает ход, обновляет память и индекс после ответа; **сцену не задерживать**.

**Не делать:**

- не писать в `HOT.json`, `GM_ONLY.json`, `archive/`, `recovery/cast/`, `recovery/FAST_SCENE.json`: это делает код;
- не составлять квитанций памяти, сводок, пересказов и аудитов хода;
- не читать перед ходом **все** каталоги и протоколы подряд: использовать адресный поиск по шардированному индексу;
- не открывать `docs/legacy/` и файлы с пометкой «заменён»: это история правок, правил там нет;
- не добавлять сюда и в GM_CORE новые разделы «P0». Поправка игрока к канону идёт в `d.canon+` хода. Поправка к манере ведения заменяет строку в GM_CORE, а не дописывается сверху.

## Разработчик

- Код `rpg_engine/`, тесты `python -m unittest discover -s tests`. Только стандартная библиотека.
- Живая память: `rpg_engine/hot.py`; общая историческая эвристика: `rpg_engine/heuristic_history.py`, вызывается при `hot-fold` и автоматически в `gm-packet`/`scene-memory`; прямой поиск `history-heuristic`. Устройство: `docs/ARCHITECTURE.md`.
- Историю на `game-state/shiki` не переписывать и не удалять; исходники сессий хранить дословно в `archive/`.
- **После каждой сессии** — порядок хранителя `docs/KEEPER.md`: состояние, `memory-metrics`, облик новых лиц, поправки на страницах, `memory/EVAL.jsonl` и `wiki-eval`, закрытие событий и 2–3 события на следующую сессию. HOT: норма до 80 КБ, предел 90; `GM_BRIEF`: цель 32 КБ, предел 48.
- Этот файл одинаков на `main` и `game-state/shiki`. Размер этого файла, GM_CORE и навыка держат тесты `tests/test_instruction_budget.py`: рост означает, что правило надо заменить, а не добавить.
- Скрытая правда живёт только в `recovery/GM_ONLY.json` и файлах `*GM_ONLY*`. В `HOT.json`, коммитах, PR и ответах игроку её нет.
