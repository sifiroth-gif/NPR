# Общая историческая память NPR: рабочий маршрут

**Действующий код:** `rpg_engine/heuristic_history.py`, `rpg_engine/scene_memory.py`, `rpg_engine/scene_gate.py`, `rpg_engine/preparation.py`, `rpg_engine/hot.py`. Предсценная проверка уже сказанного NPC — в [SOURCE_REVIEWED_SCENE_GATE.md](SOURCE_REVIEWED_SCENE_GATE.md).

Цель — поиск по **всей** подтверждённой доступной истории игры. Не существует тематических частных поисков «для Хаку», «для медицины» или «для последней сессии». Смена сеттинга не требует переписывать список имён и событий. Поисковая выдача не становится каноном без проверки первоисточника.

## Три уровня данных

1. **Текущее состояние**: `recovery/HOT.json`, `recovery/GM_ONLY.json` (раздельная видимая и скрытая информация), `recovery/TURN.json` (наиболее свежая запись). Текущий ход имеет приоритет перед устаревшей свёрткой.
2. **История без потерь**: `archive/session-001.md`; для сессий с проверенной навигацией — `archive/session-NNN-index.json` + `archive/session-NNN-source.md`; для журналируемых сессий — `archive/session-NNN-turns.jsonl`. Номер будущей сессии обнаруживается по имени, не по вручную составленному списку. Вторая и третья сессии включают только строки `status: played`, а отменённые источники не используются для фиксации событий. В первой сессии пока нет построчной таблицы статусов, поэтому все найденные фрагменты помечаются `archived_source_review_required`. Это ограничение доказательности, **не** исключение первой сессии из поиска.
3. **Канон и исправления**: `campaigns/shiki/characters`, `continuity`, `locations`, `contract`, `lore`, `archive/shiki-canon.jsonl`. Поздняя поправка игрока имеет приоритет над противоречащим ранним эпизодом, но поисковик не удаляет исторический источник. Различать сыгранный факт, предположение, рассказ NPC, авторскую ошибку и отменённый фрагмент.

## Встроенное выполнение

- Каждая штатная свёртка `hot-fold` **сама** обновляет `archive/heuristic-recall`, независимо от того, изменилось ли игровое время.
- `gm-packet` через `preparation.packet → scene_memory.preflight → historical_candidates` автоматически ищет по всему корпусу одновременно со стандартным SQLite/FTS и карточками.
- `scene-memory` для текстового режима и GitHub читает HOT v2 (старый FAST_SCENE — только совместимость), учитывает TURN впереди свёртки и пользуется тем же историческим поиском. При устаревшем индексе формирует новое **временное представление** из источников.
- `history-heuristic` — тот же поиск для адресной технической проверки, а не отдельная «память», которую ведущий должен вручную включать.

Пример локального вызова:

```bash
python -m rpg_engine history-heuristic 'кто первым заключил договор' \
  --state-dir /private/NPR-state --source-root /private/NPR-main --limit 10
python -m rpg_engine scene-memory --state-dir /private/NPR-state \
  --source-root /private/NPR-main --player-action 'новая заявка'
```

## Как устроен индекс для 100+ сессий

`archive/heuristic-recall/manifest.json` → `route-sNNN.json` → `shard-NNN.json`.

Производные файлы лежат в **приватной ветке кампании**, исходные журналы не переписываются. Сначала по нормализованным терминам запроса выбирается группа источников, затем подходящие небольшие фрагменты. Маршрутизатор использует детерминированный Bloom-фильтр (32768 бит, четыре хеша): он допускает ложные совпадения, но не должен отбрасывать **точно** проиндексированный термин. Для русских форм дополнительно индексируются короткие приставки слов. Совпадение фильтра — только повод открыть фрагмент, не доказательство факта.

Для GitHub-режима ведущего: прочитать манифест, выбрать группы через `might_contain` (или проверку идентичного Bloom-алгоритма), открыть только их `route-*.json`, затем выбранные `shard-*.json`. На найденном фрагменте проверять `source_sha256`, строки `lines`, `kind`, дату и поздние исправления. Если фильтр или API недоступны, открывать манифест/архив по найденному адресу и явно фиксировать пробел; не объявлять отсутствие результата доказательством отсутствия события.

Релевантность основана на словоформах, транслитерации, сходстве редких терминов и их документной частоте. Действие игрока, локация и персонажи ищутся **независимыми запросами**, чтобы исторический эпизод в другом месте не терялся в общем AND-запросе.

## Проверка и ограничения

```bash
python -m unittest discover -s tests -q
python -m rpg_engine.recall_audit /private/NPR-state
```

Рабочая свёртка проверяет охват обнаруженных сессий, число фрагментов и SHA каждого шарда и маршрута. `archive/heuristic-recall/audit.json` содержит измеренные время загрузки и длительности тёплых локальных запросов. Эти показатели **не включают** сеть GitHub, запуск моделей и создание сцены; нельзя выдавать их за полное время ответа ChatGPT. Эвристика не заменяет первичный источник и никогда не даёт NPC знания только из-за присутствия имени в тексте.

Когда история растёт, записи старых сессий остаются в собственных архивах; меняется лишь удаляемый производный поисковый слой. При выявлении пропуска надо расширить **общий формат чтения источника**, а не добавлять сюжетный словарь из частных исключений.
