# Предпубликационная проверка C4

На обычном ходе: один NEXT, составить сцену и её TURN в уме, сверить шесть
пунктов NEXT.preflight, исправить существенное до публикации, затем показать
сцену и один update_file. Не записывать декларативный чеклист в TURN и не
ждать CI. Проверять неизвестный значимый факт адресно, прочитанный источник
не перечитывать. При задержке свёртки — подтверждённые локальные записи.

1. Заявка: все действия и дословная речь; прерванное остаётся попыткой;
   никаких добровольных решений за Шики.
2. Источник: поздние поправки, реестр, актуальное состояние, источник
   конкретного факта; неизвестное не утверждать.
3. Перспектива: доступный результат полностью, знание NPC по каналу,
   GM_ONLY остаётся закрытым.
4. Цена: время, кости подряд, реальная активация и условия способности,
   расход, медицинская морфология/функция/кровь отдельно.
5. Мир: сроки, доступность вести, мотив и индивидуальная реакция NPC,
   никакого нового конфликта только ради окончания сцены.
6. Дельта: соответствие прозе, точные ID, раны, ресурс, вещи, состав.
   Не считать обязательство исполненным, если его не показали/не решили.

В локальном CLI (не обязательный сетевой запрос):
`python -m rpg_engine.preflight NEXT.json draft.json [--receipts receipts.json] [--used capability.id]`.
receipts — точные подтверждённые записи с SHA по overlay. used — явный
локальный список применяемых способностей; не добавляется в TURN и не
угадывается по названию в прозе. mechanical_ok проверяет структуру,
предшественника, время, выбранные кости, заявленную полосу/категорию,
цену, неоднозначные раны и некоторые правила формата. Результат содержит
review и checklist; механический успех НЕ доказывает художественное
качество, истинность сведений, соответствие текста дельте или полноту заявки.
Оценка ресурса на конец хода — верхняя граница; момент применения и внешний
источник проверяет ведущий. Проверка не меняет файлы, не бросает кости,
не выполняет ход, не публикует ничего и не обращается к GitHub.

После публикации существующие live_scene.validate_admission,
memory_guard, continuity_guard, fight и prose_lint остаются диагностикой.
Новая postcheck предупреждает о потерянной/перефразированной длинной
реплике, не отклоняет сыгранное. Исторические ходы не пересчитываются.
Смысловую проверку нельзя гарантировать в обычном чат-интерфейсе:
он не запускает этот Python автоматически; контракт NEXT и GM_CORE
обязателен, CLI для разработки/интеграции. Не создавать фиктивных attestations.
