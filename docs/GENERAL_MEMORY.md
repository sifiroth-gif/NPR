# NPR General Memory v2

Технический регламент общей источниковой памяти. Применяется к любому сеттингу: персонажи, пациенты, организации, предметы, места, события, изменения здоровья и состояния, отношения, процессы и часы автономного мира.

## Источники идей и границы переноса

| Проект | Использованное решение | В NPR |
| --- | --- | --- |
| Hindsight (vectorize-io/hindsight) | Источниковые факты; независимые каналы lexical, graph, temporal, semantic | Детерминированное объединение точного ID, лексического совпадения, времени и зарегистрированных связей; существующий semantic_recall остаётся необязательной вспомогательной подсистемой |
| memU (NevaMind-AI/memU) | Единая точка выдачи контекста и автоматическое обновление после завершения хода | TURN → hot-fold → индекс памяти → GM_BRIEF; тяжёлая работа не выполняется в критическом пути каждой сцены |
| OpenViking (volcengine/OpenViking) | Разделение ресурсов, памяти и инструкций; L0/L1/L2 | L0: подтверждённая сущность и её факты; L1: исторические и актуальные карточки; L2: конкретные первоисточники и связи |

Это архитектурная адаптация; ни один сервер третьих лиц не запускается. Приватное содержание остаётся на собственной игровой ветке GitHub.

## Хранилища и авторитет

1. Источники: дословные подтверждённые архивы, прямые исправления игрока, утверждённые карточки.
2. Проверенные факты: recovery/ENTITY_SEED_GM_ONLY.json и явно указанные d.entity_facts в сыгранном TURN.
3. Оперативные проекции: HOT, GM_ONLY, recovery/cast, предметы, сюжетные линии и часы. Их содержимое — источниковые подсказки, не автоматически новое доказанное утверждение.
4. Производные каталоги: recovery/ENTITY_LEDGER_GM_ONLY.json и recovery/GENERAL_MEMORY_GM_ONLY.json. Можно пересоздать из фактических источников.
5. Быстрый пакет ведущего: recovery/GM_BRIEF.json с entity_memory и general_memory. Событие в архиве не исчезает, если NPC или предмет отсутствует в текущей сцене.

Принцип: метки source_candidate_only и explicit_edge_candidate не означают истину. Устанавливать причинность, знание NPC и факт мира можно только после проверки независимого источника и доступа персонажа к информации. Поздние прямые исправления игрока имеют приоритет. Временные факты имеют event_at, observed_at, valid_from и valid_until; возраст при обнаружении не эквивалентен текущему возрасту.

## Покрытие общей памяти

Индекс строится из всех архивных карточек NPC, всех структурированных записей игроков и ведущего, из текущих и удалённых предметов, связанных держателей предметов, закрытых и активных процессов, датированных мест, событий развития и канонических исправлений. Для первых сессий, не имеющих JSONL, используются точные диапазоны строк исходных Markdown-архивов. Всё, что обнаружено только поиском в прозе, остаётся кандидатом, пока не подтверждено.

Новый объект, встретившийся лишь как неопознанный идентификатор, получает статус unresolved. Система не генерирует ему биографию из названия или соседства в тексте.

## Работа мастера

- Для обычного хода прочитать готовый приватный GM_BRIEF. Короткий слой L0 включён без отдельного поиска.
- При обращении к давно отсутствующему NPC, предмету или месту запросить memory-context с текстом заявки. На L1 доступны карточки, на L2 — источники.
- В новом ходу записывать структурированные изменения один раз в d.entity_facts, указывая field, value, source и при необходимости срок действия, supersedes и область знания. Дополнительного сохранения от мастера нет.
- Если описывается новое объективное утверждение в review.entity_claims, оно сверяется с доказанным фактом либо новым событием. NPC-версии размечаются actor/channel и не становятся истиной автоматически.
- Перед публикацией существенного нового фактического утверждения применять live-preflight с параметром turn, включая проверку источников и узкий контроль буквального противоречия в прозе.
- GitHub Actions после публикации восстанавливает производные индексы и GM_BRIEF, не меняя игровые события.

## Команды

Из корня репозитория, состояние восстановлено в каталоге _state.

    python -m rpg_engine memory-context --state-dir _state --action "обследую шестого" --level 0
    python -m rpg_engine memory-context --state-dir _state --action "куда исчез прежний капитан" --level 1
    python -m rpg_engine memory-context --state-dir _state --action "что было с пробиркой" --level 2
    python -m rpg_engine live-preflight --state-dir _state --action "осматриваю пациента" --memory-level 2
    python -m rpg_engine live-preflight --state-dir _state --action "осматриваю пациента" --turn draft.json

## Проверяемые требования

- Любой давно исчезнувший NPC или предмет восстанавливается по исходным ID и альтернативным наименованиям, даже если отсутствует в текущем составе.
- Факты не пропадают при свёртке, переоткрытии чата или смене сессии.
- Временные характеристики и отдельные знания NPC не смешиваются с абсолютной истиной.
- Индекс пересоздаётся детерминированно, а старые источники остаются адресуемыми.
- Сцены быстро готовятся из малого пакета. Подробный поиск запускается адресно.
- Смена сеттинга использует пустую кампанию и её собственную ветку сохранения; старый канон не импортируется автоматически.

## Ограничения

Полная автоматическая семантическая проверка произвольного художественного текста без отдельного языкового анализатора недостижима. Текущий контроль выявляет явные структурированные конфликты и часть очевидных противоречий, но прохождение проверки нельзя выдавать за полную гарантию. Автоматическая регистрация новых фактов по тексту намеренно ограничена: пропуск кандидата лучше, чем выдуманный канон.
