# Директивы игрока (B3)

Постоянные требования сохраняются до явной отмены. `NEXT.directives.standing`
— действующие правила, `standing_ids` — их стабильные ID в том же порядке.
`recent` — только недавние неясные поправки для уточнения, не постоянный приказ.
Вопросы и разовые просьбы исполняются в своём ходе, остаются в первичном TURN,
не становятся правилами. Существующий curated seed не переписывается;
ID для старых строк детерминирован содержанием. Новые события хранятся в
HOT.directive_events, не обрезаются KEEP/RECENT_TURNS, переносятся при смене
сессии и откатываются при amend. Архив первичных ходов не меняется.

Чёткие постоянные обращения («всегда», «впредь», «в каждой сцене») сохраняются
автоматически, если не содержат вопроса, разовой просьбы или отмены. Сложную
смешанную формулировку нельзя надёжно классифицировать по ключевым словам:
уточни или сохрани только явно постоянный фрагмент через операцию.
В обычном чате ведущий соблюдает этот контракт; код проверяет цитату.

`d.directive_ops` — необязательный массив операций:
- add: {"op":"add","quote":"Впредь пиши ...","text":"Впредь пиши ..."}
- revoke: {"op":"revoke","id":"dir_...","quote":"Отмени ..."}
- replace: {"op":"replace","id":"dir_...","quote":"Замени ...: впредь ...","text":"впредь ..."}
Цитата должна дословно входить в обращение игрока к ведущему; text — дословная
часть цитаты. Для отмены/замены нужен однозначно установленный ID, не догадка.
Если адресат отмены неясен, не отменяй правило по похожим словам.
По умолчанию scope=shiki. scope=general — только явное «для всех игр» и т.п.;
замена без scope наследует прежний. Протокол ноль переносит действующие общие
правила, не отменённые и не кампанийные. Исходный seed сохраняется как источник.
При отставании NEXT учитывай подтверждённую локальную операцию один раз.
