# Когнитивный контур NPC (HOT)
 
Введён по поправке игрока s18.text.101. Не является психометрической шкалой и не
заменяет характер NPC, правила источников, компетентность и dread. Никакого
нового знания из броска: он задаёт потолок интерпретации уже доступного
стимула. Никакой обязательной лестницы эмоций.

## Механика

1. **Факт** — персонаж увидел, услышал, прочитал. Уровень received доступен
   без успеха, но только при реальном канале. Не считать, что получатель
   автоматически понял механизм или намерение.
2. **Интерпретация** — отдельный воспроизводимый d20 по идентификатору хода и
   NPC, без расходования боевых костей и бросков чужих планов. Код вычисляет
   потолок по формуле roll + aptitude + 4 в подтверждённой области.
   Нейтральная базовая aptitude = 0; индивидуальные калибровки 0–2 и
   области перечислены в cognition.PROFILES. Это игровые параметры, не IQ.
   Неизвестный NPC не получает экспертности из ранга.
3. **Сложность**: routine = 7, new = 13, disruptive = 19. Разность score−DC
   ≤−5: received; −4…−1: partial; ≥0: hypothesis; ≥4 и explicit:
   understood. Наблюдаемые косвенные признаки (signs) никогда не дают выше
   hypothesis; непрояснённое (opaque) не выше partial. Explicit — именно
   доступное объяснение смысла, а не знание ведущего. Полученный потолок
   не принуждает NPC к лучшему выводу. Для понимания очевидного факта
   не требуется проверка интерпретации: записать received.
4. **Аффект**: surprise, confusion, curiosity, doubt, fear, anger, joy,
   denial, interest, calm, none. Не выводится из успешности броска.
   Выбирается из характера, прежних событий и интереса NPC. При
   disruptive отсутствие реакции недопустимо; спокойствие требует
   индивидуального основания. При обычном событии none допустим.
5. **Память**: отдельный реестр тем в закрытой части psyche NPC. Следующий
   NEXT даёт только недавние темы; полный реестр остаётся в GM_ONLY.
   Повтор той же улики (нормализованный SHA-256 по теме) не повышает
   прежний уровень. Новое свидетельство, объяснение или проверка может
   изменить понимание. Не путать ошибочную гипотезу NPC с фактом мира.

## Контракт хода

NEXT.cognition выдаёт идентификатор хода, запасной бросок для нового
участника, формулу; NEXT.present.<id>.cognition — индивидуальный бросок,
aptitude, domains, краткие темы, последняя dread-интерпретация.
Новые участники без записи в пакете используют запасной бросок; старые
кости при отставании NEXT не использовать. Структурный формат:
 
```json
{
  "d": {
    "cognition": {
      "kankuro": {
        "topic": "shiki_agreements",
        "domain": "politics",
        "novelty": "new",
        "evidence": "signs",
        "stimulus": "На верстаке лежали три соглашения.",
        "outcome": "received",
        "affect": "surprise",
        "visible": "Канкуро невольно присвистнул."
      }
    }
  }
}
```

stimulus и visible — точные фрагменты gm; interpretation обязателен для
partial/hypothesis/understood; basis обязателен для спокойствия при disruptive.
topic — стабильный ASCII-ключ, не меняется ради повторной проверки.
Одна запись на NPC за значимый ход, до 16 NPC. Выбирай наиболее значимый
стимул, а не протоколируй каждую бытовую фразу. При новом knows+, локальном
knowledge_event, изменении dread.reads или характерном утвердительном
маркерe вывода код ждёт запись. Простая реплика без нового знания/трактовки
не требует её. Вопрос, заданный из незнания, не приравнивается к выводу.

Пример из s18.text.100: Канкуро видел три договора, знает о розыске, может
удивиться документам и спросить, разыскивает ли Кири Шики. Не вправе из них
получить факт уже состоявшихся переговоров. Гипотеза не записывается в
knows+ как достоверное знание. Новый факт о переговорах — только если
Шики или другой доступный источник его сообщит.

## Интеграция и границы

- cognition.validate: структурная проверка TURN.
- cognition.review/apply: сверка потолка, источника и реакции при
  свёртке, запись принятого когнитивного состояния в GM_ONLY. Ошибочные
  записи не продвигают когнитивный реестр; checks содержит причину.
- nextpack: расчёт до хода; preflight.inspect проверяет тот же контракт
  в черновике, overlay удаляет устаревшие броски, merge перенаправляет
  записи при объединении идентичностей.
- Автоматический контроль отсутствия записи применяется с s18.text.102;
  исторические ходы не переосмысливаются. Уже показанная сцена не
  откатывается автоматически при смысловом замечании свёртки.
- Лексические маркеры — эвристика, а не доказательство причинно-следственного
  вывода. Код не может самостоятельно подтвердить смысловой выбор
  novelty/evidence/affect, подлинность профессии или тот факт, что фрагмент
  прозы действительно доступен NPC. Это остаётся предметом контроля
  источников и предыгровой подготовки. Нет классификации эмоций по
  автоматически сгенерированным физиологическим жестам.

Тесты: `python -m unittest tests.test_cognition` либо штатный
`python -m unittest discover -s tests`.
