# NPR: проверяемая память сущностей (первый контур)

## Принцип

Сохранённый журнал — свидетельство, но не автоматически доступная память. У пациента, предмета, места и каждого значимого персонажа должен быть устойчивый ID независимо от наличия карточки NPC или `scene.present`.

- Источники истины: дословный сыгранный журнал, явные исправления игрока и проверенные карточки в `ENTITY_SEED_GM_ONLY.json`.
- `ENTITY_LEDGER_GM_ONLY.json` — производный индекс, заново собираемый из начальных проверенных карточек и `d.entity_facts` в архивированных ходах. Его нельзя редактировать руками.
- `GM_BRIEF.entity_memory.activated` — компактные доказанные атрибуты сущностей, упомянутых местом, положением, ситуацией или составом сцены, даже если их нет в `scene.present`.
- `live-preflight --action "обследую шестого"` дополнительно поднимает карточку по алиасам обращения до написания сцены, без необходимости исторического вопроса.
- Прямые утверждения не появляются из похожести текста. Факт требует `field`, `value`, `source`. Неизвестные характеристики остаются неизвестными.

## Проверяемое воспроизведение ошибки

Оригинальная сцена реципиента № 6 установлена в `archive/session-005-source.md:L3057` и повторена в исправлении `archive/shiki-canon.jsonl:s08.text.005`. Реципиент — мальчик примерно шестнадцати лет. Его не было в `scene.present` и `HOT.cast`, однако он находился у постели во время осмотра.

Реестр находится **в приватной ветке сохранения**, а не в исходниках `main`. Он содержит только источниковые факты, не заменяет динамику болезни, травм и состояния, которые меняются через события.

## Формат будущих ходов

Явное обновление через обычный `TURN.json`, без дополнительной записи мастером:

```json
{
  "d": {
    "entity_facts": {
      "recipient6": {
        "aliases+": ["пациента №6"],
        "facts+": [
          {
            "field": "medical_status",
            "value": "наблюдение после бронхоскопии",
            "source": "s08.text.006",
            "authority": "played"
          }
        ]
      }
    }
  }
}
```

Противоречащий установленной характеристике факт должен явно перечислить ID старых доказательств в `supersedes`, если есть игровое событие или указание игрока, допускающее замену. Без этого он не становится активной истиной, а переносится в список конфликтов. В `live-preflight --turn` такая запись блокируется до публикации.

Важно: новый возраст или новая фамилия **не должны заменять** старый возраст/имя только из-за более поздней даты. Для возрастов указывается дата наблюдения/начала; для временных параметров — отдельная история изменений. `age_at_discovery` не означает `current_age`.

## Жизненный цикл

1. На межсессионном переходе извлечь проверяемые устойчивые факты из дословных записей и сверить их с игроком/каноном, прежде чем сделать исходной карточкой.
2. `hot-fold` восстанавливает весь производный индекс из исходной карточки и структурированных ходов, не добавляя факты по пересказу.
3. При формировании `GM_BRIEF` включить все сущности, определённые в ситуации/позициях, и их обязательные атрибуты.
4. При новом обращении вызвать предсценный маршрут с `--action`, когда новая сущность не была известна из уже загруженного пакета.
5. Прежде чем показывать игроку сцену, проверить `live-preflight --turn` и исправить противоречия; контроль после публикации годится только для диагностики.
6. В регрессионных тестах намеренно убрать пациента из NPC-состава, выполнить несколько свёрток, снова обратиться «обследую шестого» и проверить факт и ссылку на первоисточник.

## Строгие ограничения

Это первый слой. Он гарантирует восстановление **уже внесённых структурированных фактов**, но не автоматическое безошибочное извлечение каждого атрибута из произвольной художественной прозы. Полная система потребует отдельного этапа извлечения кандидатных фактов, их подтверждения на основе первоисточника и проверок фактических утверждений свободного текста до показа игроку.

Нельзя выдавать ассоциацию, суммаризацию или векторное совпадение за факт. Нельзя без разрешения пересылать приватную кампанию внешним память-сервисам.

Запросы к реестру — чтение; обновление только по явным дельтам и исходным карточкам. Тяжёлая переработка истории выполняется в GitHub Actions после хода, а не на критическом пути диалога.
