# NPR — причинное разрешение боёв (ядро)

## Источник и границы переноса

Адаптировано из `sifiroth-gif/Bleach-RPG-/docs/GM_RULES.md` (§ 8–9), `docs/GM_PRE_SCENE_RECALL.md`, `docs/WORLD_AUTONOMY.md`, `docs/GM_CHAT_RNG_BRIDGE.md`:
- освоенное, бесспорное действие не проверяется броском;
- исход определяют **геометрия, наблюдение, время и реальные возможности сторон**;
- не существует обязательных универсальных раундов, бесплатных реакций и абстрактной полосы HP;
- травмы, усталость, расход энергии и уже начатые воздействия сохраняются;
- только реальная остаточная неопределённость требует источниково подготовленного, повторяемого RNG;
- ведущий не управляет персонажем игрока;
- противник не бессилен во время длинной заявки, но реагирует только если мог заметить и успеть.

Не перенесены Кидо, реиацу, иерархии сил Bleach, конфликтующие со структурой Naruto, и тяжёлая инфраструктура world_autonomy: у NPR уже свой лёгкий движок SQLite и защищённый HMAC RNG.

## Рабочие модули

`rpg_engine/combat.py` не заменяет `rpg_engine.engine.Campaign`, а дополняет его:

| Функция | Договор | Гарантия |
|---|---|---|
| `validate_frame(frame)` | `NPR-COMBAT-FRAME/1` | 2D-геометрия, индивидуальные наблюдения, сознание, подвижность, освоенные навыки и техники, ранения, ресурсные диапазоны |
| `assess_attempt(frame, attempt)` | `NPR-COMBAT-ATTEMPT/1` | Проверяет доступность, досягаемость, помехи, опору, уже занятое время, источники действия и окно реакции. **Не определяет попадание.** |
| `validate_bands(bands)` | диапазоны 1–100 | Никаких постфактум изменяемых дыр и перекрытий |
| `contested_roll(game, ...)` | существующая `Campaign.roll` | Устойчивые ID, HMAC, сохранение вероятностного договора в `purpose`, нет двойного броска |
| `apply_outcome(frame, outcome)` | `NPR-COMBAT-OUTCOME/1` | Причинные изменения ранений, дыхания/сознания, чакры, выносливости, положения, боевой готовности; без исчезновения раны |
| `outcome_world_event(...)` | обычное событие `NPR` | Приватная операция `set_fact` к `combat:<frame.id>/frame`, без новой схемы БД |

Приватная проверка `campaigns/shiki/maintenance/prepare_reviewed_turn.py` при `p0.combat_present=true` требует отдельный `knowledge_review.combat_review` формата `NPR-COMBAT-REVIEW/1`. Он связывает этот снимок, реальные действия (включая подтверждение, что Шики действительно объявил атаку), актуальные уровни Шики из `lore.json`, обоснованное окно ответных действий, доступные ему тактические наблюдения и зарегистрированные результаты. При завершённом результате он требует закрытую операцию сохранения `outcome_world_event` внутри `turn.events`; заявленное случайное разрешение должно совпасть с уже зарезервированным результатом RNG. Пустое боевое состояние в небоевом ответе не требуется.

### Ключевой запрет метазнания

Полный приватный кадр может содержать фактическую позицию невидимого врага, которую знает только ведущий. Шики видит лишь доступные признаки (свои наблюдения и известные источники). Предсценическая проверка **не** выдаёт приватный кадр игроку; художественный ответ передаёт только проверяемые видимые сведения, включая телесные предвестники действий. `KNOWLEDGE_POLICY.json` и `SCENE_PREP_PRIORITY.md` действуют одновременно.

## Боевой контракт времени

Часы `frame.at_ms`, `attempt.start_ms`, `duration_ms`, `outcome.at_ms` — относительная монотонная шкала внутри живого игрового эпизода. Она не отменяет обязательную дату/время в художественном заголовке. Это ориентир, основанный на данной дистанции, подготовке и способности видеть действие, **не универсальные скорости тела**. Если нет оснований вычислить реакцию — фиксировать неопределённость, а не придумывать автоматическое уклонение.

Возможная реакция `possible_not_guaranteed` означает лишь наличие времени и наблюдения, не успешный блок. `not_yet_detected` не гарантирует попадания. Бессознательное тело не выполняет осмысленную добровольную защиту. Если не хватает физической дистанции для скальпеля, нужно реально приблизиться и учесть вмешательство противника.

## Расходы и повреждения

Качественные интервалы `ready`, `strained`, `low`, `depleted` обозначают проверяемое состояние чакры и выносливости. Действующая техника обязана иметь описанный расход чакры, физическое перемещение/атака — стоимость усилия. Обычные метательные сенбоны и кунаи не тратят чакру сами по себе; чакровая модификация — другое действие. Функциональная травма задаётся **местом**, **механизмом**, **тяжестью** и **нарушенными функциями**, а не числом HP. Повреждение не удаляется из следующего снимка без лечения/времени/иной причины. Вся затратная информация фиксируется в законном исходе, не дублируется за один удар.

`Shunshin` нельзя применять как подмену `taijutsu` при точном контактном ударе; при корректной геометрии он даёт реальное быстрое перемещение, не телепортацию. `raiton=0.5` не является освоенной дальней электрошоковой атакой. Медицинские манипуляции должны следовать возможностям и анатомии, а исходы экспериментов и ранее не освоенных техник не предписаны заранее.

## Боевой пример данных

Синтетическая оценка одного действия:

```python
from rpg_engine.combat import assess_attempt
frame = {
    "format":"NPR-COMBAT-FRAME/1", "id":"test.1", "at_ms":0, "player_id":"shiki",
    "actors":{
        "shiki":{"position_m":[0,0],"consciousness":"alert","mobility":"normal",
          "chakra":"ready","stamina":"ready","perceives":["enemy"],
          "skills":{"shunshin":3.5,"taijutsu":1.5},"learned":["shunshin"],"injuries":{}},
        "enemy":{"position_m":[3,0],"consciousness":"alert","mobility":"normal",
          "chakra":"ready","stamina":"ready","perceives":["shiki"],
          "skills":{"taijutsu":2},"learned":[],"injuries":{}}
    }
}
attempt = {
    "format":"NPR-COMBAT-ATTEMPT/1", "id":"test.move.1", "actor":"shiki",
    "kind":"move","intent":"Занять фланг", "start_ms":0,"duration_ms":300,
    "source":{"kind":"player_declaration","ref":"#рывок во фланг#"},
    "ability":"shunshin","technique":"shunshin",
    "destination_m":[1,1],"path_clear":True,
    "chakra_cost":"minor","stamina_cost":"minor"
}
assessment = assess_attempt(frame, attempt)
# assessment сообщает физическую осуществимость движения и окна;
# не превращает намерение во вторую незаявленную атаку и не решает бой.
```

Это пример кода, а не подтверждённое действие Шики.

## Применение в текущей кампании

Для каждого значимого боя ведущий предварительно составляет причинный кадр, затем отражает в тексте **доступные Шики** сведения и объявленную попытку; если исход бесспорен, не бросает кость. Если исход действительно зависит от случайности, сначала фиксирует диапазоны, резервирует `Campaign.roll` под стабильным ID, затем готовит точный художественный ответ. Уже зарезервированный бросок создаёт `pending` без `packet`; подготовка новой сцены может использовать этот же ID без подтверждения несуществовавшего опубликованного черновика.

Полный текущий протокол персонажа: `campaigns/shiki/COMBAT_PROTOCOL.md`. Личный контроль, память NPC и наблюдательность Шики имеют максимальный приоритет независимо от результата проверки.

## Ограничения

Код проверяет объявленные расстояния/времена/ресурсы, источники действий и целостность изменений, **но не может доказать правильность авторского описания анатомии, достоверность траектории, способности видеть или сбалансированность назначенных шансов**. Это остаётся обязательным причинным суждением ведущего. Новых таблиц кампании не создаётся, существующие `game-state/shiki` и ревизии не модифицируются самой установкой кода.
