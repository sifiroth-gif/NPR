# Планировщик сюжета и событий

Код: `rpg_engine/plot.py`. Состояние: `recovery/GM_ONLY.json` → `plot` (только ведущий).

## Зачем

Модель-ведущий склонна продолжать любую линию бесконечно: каждая разгадка рождает новую преграду.
Поэтому у каждого события конец записан с рождения, а код считает сцены и напоминает развязать.

## Уровни

| `kind` | что это | конец |
|---|---|---|
| `main` | сквозной сюжет игры, лейтмотив | `question`, `endings`; держит главы |
| `chapter` | глава сквозного сюжета | `question`, `endings`, `limit`; следующую открывают после закрытия |
| `side` | побочное событие рядом с главой | `question`, `endings` 2–4 (с провалом и «ничего»), `limit` |
| `scene` | случайная сцена на 1–2 обмена | предел по умолчанию 2 сцены; вопрос не обязателен |

`limit`: `scenes` (сколько ходов событие развивалось) и/или `until` (игровое время).

## Запись в ходе

Открытие (один ход):

```json
"d": {"plot": {
  "v7": {"kind": "side", "parent": "ch2", "question": "…", "endings": ["…", "провал", "ничего"],
         "limit": {"scenes": 4}, "threads": ["v7"]},
  "ch3": {"kind": "chapter", "parent": "main", "status": "queued", "trigger": "…"}
}}
```

Следующие ходы: `"plot": {"v7": {"touch": true}}`, развязка: `"plot": {"v7": {"closed": "исход"}}`.

- Любая запись события в ходе засчитывает одну сцену (не больше одной за ход).
- Изменение связанной линии `d.threads` (поле `threads`) тоже засчитывает сцену.
- `closed` переносит событие в `plot.closed` (последние 60).
- `status: "queued"` — ждёт `trigger`, сцены не считает; `"active"` — открывает.

## Что делает свёртка

Замечания `kind: "plot"` в `recovery/CHECKS.json`:
- событие без `question` / `endings` / `limit`;
- событие на пределе: «разреши следующей сценой одной из концовок, новых преград не вводи»;
- активных `side` + `scene` больше 5;
- у `main` нет активной главы (подсказывает первую в очереди).

Ведущему план виден в `GM_BRIEF.plot` и на странице `memory/PLOT.GM_ONLY.md`;
`memory/SCENE.md` показывает только число идущих событий.
