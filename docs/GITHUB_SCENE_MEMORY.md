# NPR — обязательная память и поиск перед КАЖДОЙ сценой

**Статус: P0, действует для всех последующих ходов.** Протокол перенесён из подходов Bleach `gm_scene_recall` + `gm_hybrid_recall` + `gm_event_graph` и встроен в реальный NPR-цикл. Недостаточно просто создать модуль: подтверждение выполнения поиска должно сопровождать каждый новый опубликованный текстовый ход.

## 1. Два рабочих режима

**При актуальной SQLite:** `python -m rpg_engine --db campaign.sqlite gm-packet --mode focus --player-action "<ТОЧНАЯ ЗАЯВКА>"`. Это **автоматически** вызывает `rpg_engine.scene_memory.preflight` наряду с обычным пакетом: текущая локация, NPC, ввод игрока, память SQLite с FTS5/BM25 и причинным графом, канонические файлы персонажей, локаций и событий. Режим `scene` отличается объёмом остальных карточек, но не отключает память. Не требовать `--query` для включения поиска.

**Когда текстовый HOT впереди SQLite / инструментальный режим GitHub:** каждый ход начинается одновременным чтением **двух** небольших источников на `game-state/shiki`: `recovery/FAST_SCENE.json` и `recovery/SCENE_MEMORY_INDEX.json`. Исходные слова игрока используются в ранжировании **до написания сцены**. Текущий HOT важнее кэша, если индексация чуть отстаёт. Сначала выбираются релевантные источники; затем при необходимости читается **ровно конкретный** первоисточник, а не все файлы целиком. На любом компьютере с клоном репозитория соответствует команда:

```sh
python -m rpg_engine --db /path/to/state/campaign.sqlite scene-memory \
  --state-dir /path/to/state --source-root /path/to/main \
  --player-action "<ТОЧНАЯ ЗАЯВКА>"
```

Для текстового режима даже при недоступной SQLite `scene-memory` берёт действующий HOT, новые сведения из последних ходов и карточки источников. Переход на режим исторического `gm-packet` допустим только после `verify` и синхронизации SQLITE с подтверждёнными текстовыми ходами.

## 2. Непременная проверка «как это стало возможно?»

Поисковые анкеры формируются **независимо**: действия и предметы, место, участники, исследовательские способности. Не составлять один AND-запрос на всю сцену: это теряет удалённые эпизоды. Для генетики искать не только «Саю», но и лабораторную базу, предыдущие доказанные генетические проекты, связанные образцы и их статус. Для операции искать границу согласия, сохранённый уход и последствия.

Типы результатов:
- **Историческая запись:** SQLite FTS5, граф `journal_edges`, `journal_entities` и `journal_corrections`, плюс частные знания NPC; `source`, хеш и временная привязка обязательны.
- **Канон:** карточки `characters`, `locations`, `continuity`, `contract`, `lore`, отобранные архивные **индексы**, с SHA-256 источника; содержимое архива полностью не загружать без причины.
- **Семантика:** локальные multilingual embeddings из `semantic_recall.py` используются автоматически, **когда указаны** три `NPR_RECALL_CACHE`, `NPR_RECALL_MODEL`, `NPR_RECALL_MODEL_SHA` и кэш проверен. Без модели работает надёжный FTS/графовый и многоязычный понятийный поиск; **не заявлять**, что нейросетевые векторы работали, если их нет.
- **HOT:** новые события, поправки, точная граница времени; выход впереди SQLite маркировать `text_ahead_unreplayed`.

Результат поиска — **кандидат для проверки**, не всезнание NPC, не автоматическое знание Шики и не основание заполнить пробел. Сначала поздние прямые поправки игрока, затем сыгранные события; планы отмечаются как планы. Отменённые сцены не возвращать.

## 3. Использование непосредственно в чате с подключённым GitHub

Ниже — короткий шаблон единой операции **внутри Code Mode** (не вставлять в художественный ответ). Его следует применять перед каждым ответом на игровую заявку, даже когда сцена кажется простой. Данные результатов не копируются в долгий контекст: в ответе остаются только проверенные существенные факты.

```js
const repo="sifiroth-gif/NPR",branch="game-state/shiki";
const [a,b]=await Promise.all(
  ["recovery/FAST_SCENE.json","recovery/SCENE_MEMORY_INDEX.json"].map(
    path=>tools.mcp__GitHub__fetch_file({repository_full_name:repo,path,ref:branch})
  ));
const hot=JSON.parse(a.result.content),idx=JSON.parse(b.result.content);
if (idx.schema!=="npr-github-scene-memory/1") throw Error("Invalid memory catalog");
const fresh=idx.cursor.turn===hot.cursor.last_turn_id;
const action="<ТОЧНЫЙ ТЕКСТ НОВОЙ ЗАЯВКИ>";
const termlist=(action+" "+hot.cursor.location).toLowerCase().match(/[a-zа-яё0-9]+/g)||[];
const groups=[
  ["генет","genet","genom","геном","днк","dna","секвен","sequenc"],
  ["лаборатор","laborator","lab","оборуд","equipment","research","исслед"],
  ["ткан","клет","tissue","cell"],["образц","проб","sample","specimen"]
];
const terms=[...new Set(termlist)];
for(const g of groups)
  if(termlist.some(t=>g.some(k=>t.startsWith(k.slice(0,Math.min(5,k.length))))))
    terms.push(...g);
const similar=(a,b)=>a===b||(a.length>=5&&b.length>=5&&a.slice(0,5)===b.slice(0,5));
const research=termlist.some(t=>/^генет|^секвен|^днк|^биопс|^исслед/.test(t));
const ranked=idx.documents.map(d=>{
  const hits=d.terms.filter(x=>terms.some(t=>similar(t,x)));
  let score=hits.length*1.3+d.weight;
  if(research&&/locations\\/.*lab/i.test(d.source))score+=12;
  if(research&&/characters\\/shiki_/i.test(d.source))score+=3;
  return {...d,score,hits};
}).sort((x,y)=>y.score-x.score).slice(0,9);
text(JSON.stringify({
  current_turn:hot.cursor.last_turn_id,
  cache_fresh:fresh,
  current_facts:hot.story_compass?.immediate,
  selected:ranked.map(x=>({source:x.source,sha256:x.sha256,
                           score:x.score,preview:x.preview.slice(0,2),links:x.links})),
  receipt:{
    schema:"npr-memory-gate/1",previous_turn_id:hot.cursor.last_turn_id,
    index_turn:idx.cursor.turn,index_blob_sha:b.result.sha,
    player_input:action,source_refs:ranked.slice(0,6).map(x=>({
      source:x.source,sha256:x.sha256})),unretrieved:[],
    mode:fresh?"indexed_hybrid":"stale_index_plus_current_hot"
  }
}));
```

После этого проверить, какие найденные сведения **актуальны**; для спорных утверждений открыть конкретный `source` по SHA/пути и поправкам. Если каталог не успел обновиться, не считать его свежим: сравнить HOT, получить нужный документ напрямую. Не делать вывод, что источника нет, только потому, что он не попал в первые девять ранжированных карточек.

## 4. Публикация и сохранение

В новом `latest_turn` текстового HOT обязательно приложить `memory_gate` — объект `receipt` из проверки. `player_input` должен **дословно** совпадать с сохранённым ходом, `previous_turn_id` — с последним подтверждённым ходом до публикации, `source_refs` — с существующими карточками и 64-символьными SHA-256. При полном пробеле `unretrieved` перечисляет нерешённые вопросы, а не даёт право выдумать их решение. **Без этой проверки следующую художественную сцену не публиковать.**

В `scene_memory.verify_hot_memory_gate` действует автоматический контроль наличия квитанции на ходах после `s04.text.004`. Ранее опубликованные четыре хода сохранены как переходный период без квитанций. Каждый новый пуш `FAST_SCENE.json` запускает GitHub Actions `Shiki automatic live scene-memory refresh`, который регенерирует **приватный** индекс на `game-state/shiki` и проверяет результат. Записи индекса производные и не изменяют канон. При конфликте коммитов процесс перечитывает актуальную ветку, не делает force-push.

Если пользователь задаёт вопрос **Мастеру**, игровое время не двигать, новые слова/поступки Шики не выдумывать; исправление источников индексируется обычным обновлением ветки.

## 5. Долгая дистанция

Каталог ограничен по тексту каждого источника; в нём пути, термины, краткие выдержки, первичные SHA и явные ссылки, а не дубли полнотекстовых игровых сессий. Полные первоисточники остаются в архивах и SQLite. При накоплении новых событий архивируется дословная история, а индекс перестраивается без добавления несостоявшихся фактов. Секретная информация не выводится за пределы приватной ветки; источники GM-only не становятся известны NPC без события передачи знаний.

**Эталон регрессии:** «Шики секвенирует ткани Саю» извлекает `campaigns/shiki/locations/SECRET_LAB_NW_CATCHMENT_1283.json` и факты о генетических исследованиях и Нулевом Геноме. Если этот тест перестал проходить, сюжетные ответы с исследованиями нельзя публиковать без ручной проверки причины.
