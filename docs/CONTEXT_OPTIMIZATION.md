GM_ONLY: около 454 КБ психика, 290 КБ воля/обязательства (компактный JSON). Это разные бюджеты: размер файла на диске не равен токенам LLM.

## L0 / L1 / L2

Старт — AGENTS, GM_CORE, SHIKI, литературный навык и образцы, NEXT и GM_BRIEF; профиль FUSION или NEMERA. Канон, арсенал, карточки и хроники — адресно по теме и источникам. Важные изменяемые факты проверяются по последнему меняющему ходу, не по сокращённому индексу. Полная история не удаляется. В NEXT постоянные директивы и их стабильные ID сохраняются; каталог техник вне боя доступен по ссылке на реестр. В GM_BRIEF текущие вещи и обязательное оснащение полные, другие вещи Шики — индекс с точными ID и ссылками. Исторический профиль глаз сохранён, финальный реестр применяется с s15.text.132.

## Старение и проверка

Неактивные обязательства прошлых сессий сохраняют ID, kind, timestamps, offered, inactive и остальные поля, но текст уходит дословно в закрытый архив. При повторном появлении select() получает актуальный текст от источника. Неактивность не означает исполнение; активные и текущие записи не сжимаются. Детали завершённых планов архивируются до укорочения; ключи архивных записей включают хеш содержания. Новые отчёты session-close показывают байты каждого из четырёх файлов до и после. Сохранены исходные журналы, текущие сроки, незакрытые планы, канон и доступ к прошлому. Лимиты не повышаются этим изменением.

Следующий этап отдельно: измерить фактический новый пакет после CI; при необходимости шардировать скрытые данные с проверяемой гидратацией, не скрывая их в недоступном для ведущего blob. Проверить атомарность ошибки session-close: при исключении текущий workflow может публиковать промежуточный набор файлов. Не расширять агрессивное старение открытых сюжетов.
