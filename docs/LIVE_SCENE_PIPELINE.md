# Единый контур подготовки сцены NPR

Действующий код: `rpg_engine/live_scene.py`, `scene_gate.py`,
`heuristic_history.py`, `hot.py`, `__main__.py`.
Действующий приватный контроль: `game-state/shiki/recovery/GATE_POLICY.json`.

## Цепочка

```
сыгранный TURN и первичный журнал
           │
           ▼
hot-fold: время, NPC, скрытая правда, нити
           │
           ├──► HOT.json (краткий открытый контекст)
           ├──► GM_ONLY.json (тайны, сроки, скрытая память NPC)
           ├──► GM_BRIEF.json (одно быстрое чтение мастера)
           ├──► archive/session-NNN-turns.jsonl (дословные источники)
           └──► archive/heuristic-recall (общая история)
```

`GM_BRIEF` формируется автоматически из подтверждённого HOT и журнала,
имеет отпечаток содержимого и проверяется по курсору. Бюджет считается по
компактной сериализации UTF-8: целевой `TARGET_BRIEF_BYTES = 32000`, жёсткий
`MAX_BRIEF_BYTES = 48000` (константы `rpg_engine/scene_packet.py`).
Пробелы форматированного файла увеличивают размер на диске, но не рабочий бюджет.

Перед записью `GM_BRIEF` проектор строит L0: текущая сцена, все действующие
часы, актуальная глава, присутствующие NPC и их знания, источник и контекст
последствий. Ранние и последние признания остаются ссылками с ID и SHA;
небольшой набор дословных отрывков используется для быстрого продолжения.
Отложенные развязки, полные биографии и дополнительные воспоминания остаются
в L1 (`GM_ONLY`, карточки, `memory/`) и L2 (исходные сыгранные ходы).
`source_passages_truncated = true` означает только сокращение выдержек;
ссылки на первичные ходы сохраняются. Новые биографии, договорённости и
решения из обобщения не выводятся.

## Один маршрут вместо шести несвязанных проверок

`target_exceeded = true` означает превышение желаемых 32 КБ, но не потерю
критического контекста. `over_budget = true` — нарушение жёсткого лимита:
его нельзя исправлять удалением часов, неизбежных физических последствий или
единственной выдержки с первоисточником. В этом случае обязателен адресный
L1/L2-добор и отдельный разбор перегрузки, а не увеличение лимита. Обычный
эпизод не требует дополнительных GitHub-чтений.


1. Обычная сцена: прочитать готовый `GM_BRIEF` (при старте также
   `TURN`; для скрытой истины — `GM_ONLY`). Действия NPC и ближайшие
   сроки уже находятся в пакете. Нет необходимости вновь искать всю историю.
2. Исторический вопрос или новое раскрытие: использовать
   `python -m rpg_engine live-preflight --state-dir STATE --action "вопрос"`.
   Команда добавляет источник-ограниченный поиск по всем сессиям,
   граф кандидатов и перечень сыгранных раскрытий текущих NPC.
3. Составить сцену без действий за Шики. Перед предъявлением нового
   признания открыть необходимые точные сыгранные источники.
4. Для записи игрового хода в `TURN.json` всегда указывать
   `review.predecessor` = ID принятого предыдущего хода. При обращении
   к прошлому — `review.sources` с ранними и поздними раскрытиями
   действующих NPC. При заявленной новизне — `review.novelty_contrast`,
   в котором указана **новая** подтверждённая информация. Проверка
   отклоняет пропущенные исходники и устаревший курсор.
5. При временном скачке через срок автономного плана обязательно
   отразить его в `d.clocks` (исход) или `d.world_reviewed`
   (обоснованно рассмотренное событие). Никакая дата сама по себе
   не доказывает, что нападение/арест/прибытие уже случилось.
6. Знание NPC вне места сцены сопровождается `d.knowledge_events`:
   актор, содержание, ID источника и способ получения
   (`message`, `witness`, `document`, `inference`).
   `visibility="gm_only"` хранится исключительно в `GM_ONLY`,
   а не в общем списке `knows+`.

Проверка перед сохранением:

```bash
python -m rpg_engine live-preflight \
  --state-dir /path/to/state \
  --action "Что Аракава уже сообщал?" \
  --turn /path/to/draft_turn.json
```

Команда возвращает один пакет с памятью, личными пределами знаний,
активными сроками и проверкой проекта записи. При несоответствии
`--turn` возвращает ненулевой код. `hot-fold` независимо применяет
те же ограничения внутри транзакционной обработки; запрещённый ход
не должен стать новым каноном.

## Источники и граф

Граф различает `chronology_same_actor` (порядок реальных источников),
`explicit_source_record` (установленный канал получения сведений)
и `candidate_only` (лексическое соседство или эвристический поиск).
Совпадение имени в двух эпизодах **не означает** знания, участия или
родства. Результат поисковой эвристики всегда открывается по точному
источнику с проверкой поздних исправлений.

Аналогии из Bleach-RPG-: `gm_context.py`, `gm_scene_recall.py`,
`gm_event_graph.py`, `gm_hybrid_recall.py`, `gm_scene_gate.py`,
`npc_scene_fidelity.py`, `npc_psyche.py`, `world_autonomy.py`.
Нельзя копировать SQLite HEAD/HISTORY в HOT как вторую правду.
NPR хранит единственную цепь `TURN → HOT/GM_ONLY → archive`,
а производный пакет можно воссоздать без повторной игры.

## Принятые ограничения

Это механическая проверка источников и причинности, а не семантическая
гарантия безошибочной прозы. Фактический вызов инструмента **до**
показа текста пока остаётся обязанностью ведущего; GitHub проверяет
историю при сохранении, но не перехватывает уже отображённый в чате
ответ. Нельзя заявлять обратное.

Старые `knows` без указания источника сохраняются как наследованный
контекст, но не становятся доказанной осведомлённостью. Новые
структурированные события знаний получают происхождение автоматически
при свёртке. Скрытое не переносится в публичный HOT.

Смена сеттинга сохраняет механизм: меняется конфигурация персонажа,
содержание HOT, часы и первичные источники, но не универсальная
схема доверия. Для временного выключения проверок можно установить
`"enabled": false` в приватном `recovery/GATE_POLICY.json`,
не удаляя сохранение или архив.

## Проверка

`python -m unittest discover -s tests`;
`python -m rpg_engine hot-check --state-dir STATE`.
Регрессионные тесты: `tests/test_scene_gate.py`,
`tests/test_live_scene.py`, `tests/test_hot.py`.
Отдельный набор воспроизводит историю Аракавы 012–013–030 и
проверяет, что уже предъявленная папка не становится «новой» находкой.
