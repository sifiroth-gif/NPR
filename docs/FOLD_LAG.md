# Отставание свёртки: NEXT, TURN и локальная проекция

Обычный ход: одно чтение NEXT, одна CAS-запись TURN. Свёртка не блокирует диалог.
Храни в контексте точную запись TURN и полученный content_sha до подтверждения NEXT.

## Когда NEXT отстаёт

1. Сравни cursor и lag.recorded_turn с последним успешно записанным ID. Если fold_errors/state_errors — сначала исправление указанного хода. Не продолжай через ошибку.
2. Возьми только непрерывную цепочку подтверждённых записей после cursor. Применяй её один раз, без повтора расхода и действий. Следующий ID и review.predecessor — от последней принятой Git записи, SHA — её blob SHA. Неполная цепочка или чужая правка — конфликт, а не основание для догадки.
3. must старого пакета — сверка, не повторная команда. Исполненное в видимой сцене не повторять. При необходимости укажи d.must_done: [ID из must_ids] после действительного исполнения; остальные обязательства не считать исполненными. offscreen — факт мира, но не факт доставки Шики. Новый срок, новый исход плана, новое состояние ран и знание NPC, рассчитанные кодом, неизвестны до свёртки.
4. Кости предыдущего NEXT предназначены только для lag.dice_for. Никогда не переиспользуй их. При отставании можно вычислить точные новые d20 из последнего подтверждённого игрового TURN: Python json.dumps([cursor_id, cursor_at, last], ensure_ascii=False, sort_keys=True), SHA256 UTF-8; затем SHA256(b"d20|" + предыдущий digest), 12 последовательных двухбайтных big-endian чисел % 20 + 1. last = {"id", "player", "gm"}; если gm длиннее 1500 символов, gm = "…" + последние 1500, добавь gm_chars = исходная длина. OOC изменяет cursor_id, но не cursor_at/last. Если точный текст или расчёт недоступен, кости неизвестны: не решай спорное столкновение произвольно.
5. Чакра: используй последний подтверждённый баланс с lag.chakra_at; 6/час после блокировки, максимум 100, стоимость ранга/cost ×0.25, рывок 0.75. Применяй каждую подтверждённую дельту один раз; учитывай set/collapse/locked_until. Неизвестный баланс не превращай в полный. Не переиспользуй устаревшие боевые оси.

## Инструмент

`rpg_engine.overlay.project(packet, records)` — чистая функция для локального Python, без записи, CI и сети. records — список {"turn": точный TURN, "sha": content_sha успешной записи}. Возвращает новую проекцию; неопределённые derived fields изымаются, отмечаются lag_status. Не заменяет полную свёртку, не вычисляет скрытую автономию. В обычном чате автоматического исполнения Python движка нет: ведущий следует тому же контракту; при невозможности надёжно вычислить число не использует старое.

CAS: при конфликте один раз прочитай актуальный TURN. `overlay.cas_decision(expected_sha, actual_raw, intended)`: точная копия — already_written; неизменный SHA — retry_same_sha; любые иные байты — conflict, не перезаписывать с новым SHA. Новый чат не может обнаружить невидимое изменение TURN только из старого NEXT; это выявит CAS, а до подтверждения запись не считается сохранённой.
