# Память персонажей, память ведущего, непротиворечивость

Справочник к GM_CORE §3–4. Код делает всё сам при свёртке хода (GitHub Actions); ведущий пишет только `recovery/TURN.json`.

## Три слоя памяти

| Слой | Где | Кто пишет | Кто видит |
|---|---|---|---|
| Эпизоды NPC: был в сцене, ему сказали, упомянут | `HOT.cast.<ключ>.memory` (2 первых + 6 последних), полный список `archive/npc-memory/<ключ>.json` | код, по `scene.present` и `line` | ведущий; это факт сыгранного |
| Внутреннее NPC: как запомнил, отношение, чувство, намерения, характер | `GM_ONLY.psyche.<ключ>` и `GM_BRIEF.present_npcs.<ключ>.profile.inner` | ведущий через `d.cast` | только ведущий |
| Учёт вещей и состояний | `HOT.things`, ушедшее — `HOT.things_gone` | ведущий через `d.things` | ведущий |

Карточка показывает `tier`: `deep` (15+ эпизодов), `developed` (4+), `archetypal`. `GM_BRIEF.needs_profile` перечисляет присутствующих, кому для их веса не хватает граней характера: допиши `psyche` в ближайшем ходе с их участием.

## Приватные поля в `d.cast.<ключ>`

Всё необязательно. Пиши только когда в сцене действительно что-то сдвинулось.

```json
"nori": {
  "mem": "как она это запомнила, её словами и с её искажением",
  "rel": {"trust": -1, "fear": 1, "why": "Шики открыл пакет, не вскрывая"},
  "affect": {"feel": "злость, которую она прячет за протоколом", "hours": 6},
  "intent": {"take_case": {"goal": "забрать дело Хиросэ себе", "status": "committed"}},
  "psyche": {"decides": "по выгоде дела, потом по страху"},
  "why": "причина, если меняются wants/fears/voice/psyche"
}
```

- `rel`: шаги к Шики (или к `"to": "<ключ>"`). Оси `trust fear respect debt grievance attachment dependence`, каждая в пределах −5…+5. Без `why` — замечание.
- `affect` гаснет по игровым часам, не по числу реплик. Истёкшее уходит в `affect_past`.
- `intent`: `committed`, `paused`, `fulfilled`, `abandoned`. Выполненные и брошенные уходят в историю намерений.
- `psyche`, грани: `temper values deep_fear needs contradiction defense habits boundary mask decides`. `null` снимает грань.
- Смена `wants/fears/voice` или грани без `why` записывается как дрейф характера. Характер меняют события, не удобство сцены.

## Динамика NPC и автономные события

При подготовке GM_BRIEF модуль `npc_dynamics` читает **существующие** `psyche`, `intent`, `affect` и часы. Пары `values/needs`, `mask/deep_fear`, `boundary/contradiction` — вопросы о возможном разрыве личности, а не автоматические решения. `unclocked_intents` показывает committed-намерения без соответствующего срока; `overdue_owner_ids` отмечает владельцев уже наступивших событий, в том числе за пределами сцены. После решения ведущий записывает его обычным ходом: никакой скрытой самозаписи NPC нет.

`context_route` показывает точный выбор нужных сведений под сцену и заявку. При `review_required` проверь `omitted_critical` и `unindexed_present_actors`, открой точный источник, не додумывай отсутствующие характеристики. `memory-audit` — тест достижимости индекса, **не доказательство художественной непротиворечивости**. Подробнее: `docs/WHOLE_GAME_CONTEXT.md`.

## Как этим пользоваться в сцене

1. NPC отвечает из своего `memory` и `inner.remembers`, а не из знания ведущего. Чего нет в его эпизодах, `knows` и каналах, он не знает.
2. Отношение меняет поступок: при `trust −3` NPC проверяет слова Шики, при `fear +3` ищет защиту или ударит первым, при `debt` торгуется. Вежливость не отменяет оси.
3. Чувство с неистёкшим сроком окрашивает реплику и тело; истёкшее — уже прошлое, его можно вспомнить, но не играть заново.
4. `intent` со статусом `committed` NPC продвигает и без Шики; это пересекается с `clocks`.
5. Персонаж может быть нелогичен, жаден, труслив, мстителен. Психика — не оправдание доброты, а причина конкретного решения.

## Вещи, числа, раны: `d.things`

```json
"things": {
  "ampoules": {"was": {"count": 3}, "now": {"count": 2}},
  "scalpel":  {"was": {"holder": "shiki"}, "now": {"holder": "kadziura_satoru"}},
  "letter_v7": {"new": {"name": "письмо с печатью В-7", "holder": "shiki"}, "why": "передал курьер"},
  "old_note": {"gone": "сожжена в печи"}
}
```

Поля: `name holder where state count`. Переходы проверяются последовательно: `was` должно совпасть с текущим учётом, иначе замечание «contradiction». Новая вещь без `why`, отрицательный `count`, изменение вещи вне учёта — тоже замечания. Кровопотеря, швы, переломы — `state` у ключа раны (`"shiki_wound_left_side"`), чтобы следующая сцена не «вылечила» её молча.

## Замечания и отказы: `recovery/CHECKS.json`

- `checks` — мягкие замечания: противоречие учёту, дрейф характера, совпадение имён, реплика игрока вошла в сцену меньше чем наполовину, источники раскрытий. Ход уже сыгран и свёрнут; исправляй следующим ходом, не переписывай показанное молча.
- `fold_errors` — ход не свёрнут (разрыв нумерации, время назад, битый JSON). Исправь тот же `id` с `"amend": true` и прежним `review.predecessor`.
- Перед новой сценой и в начале чата прочитай этот файл; он короткий.

## Исправление хода

`amend` с тем же `id` откатывает предыдущую версию хода из снимка и применяет новую. Эпизоды NPC, хроника и учёт пересчитываются по исправленному тексту; старая версия остаётся только в истории Git.
